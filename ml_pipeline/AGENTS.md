# ML Pipeline — Детекция объекта на видео → траектория → триангуляция

## Контекст и суть задачи

В папке `data/` лежат 5 видео с камер (`Way1.FinalImage.CineCameraActor1..5.mp4`) и CSV-файлы с параметрами камер и граунд-траутом 3D-траектории объекта.

**Цель:** обучить модель детекции объекта (фура/грузовик) на каждом кадре каждого видео, затем восстановить 3D-траекторию движения через триангуляцию из 2D-наблюдений нескольких камер, и валидировать результат против известного граунд-траута.

**Ключевое преимущество:** разметка вручную не нужна — 3D-граунд-траут проецируется в 2D-пиксели каждой камеры автоматически, что даёт готовые YOLO-метки для обучения.

## Структура папки `ml_pipeline/`

```
ml_pipeline/
├── camera_calibration.py   # Этап 0-1: интринсики, экстринсики, 3D→2D проекции
├── extract_video_meta.py   # Этап 0: параметры видео (разрешение, FPS, кадры)
├── train_yolo.py           # Этап 2: подготовка датасета + обучение YOLO
├── extract_frames.py       # Этап 2: извлечение кадров из видео для обучения
├── infer_yolo.py           # Этап 3: детектинг на каждом кадре → detections.csv
├── triangulate.py          # Этап 4: триангуляция 3D-точек из 2D-детекций
├── validate.py             # Этап 6: валидация против граунд-траута
└── AGENTS.md               # этот файл
```

## Конвейер (порядок запуска)

### Шаг 1 — Параметры видео
```bash
python3 extract_video_meta.py
```
Через `cv2.VideoCapture` получает разрешение, FPS, число кадров. Записывает `runs/metadata/video_meta.json`.

> **Важно:** если разрешение видео ≠ 1920×1080, перезапустите калибровку с правильными значениями:
> `VIDEO_W=<ширина> VIDEO_H=<высота> python3 camera_calibration.py`

### Шаг 2 — Калибровка камер и авторазметка
```bash
python3 camera_calibration.py
```
- Читает CSV камер (кодировка cp1251, разделитель `;`).
- Вычисляет K-матрицы (интринсики) и R/t (экстринсики) для каждого кадра.
- Проецирует 3D-точки из `SM_AA_track.csv` на 2D-пиксели каждой камеры.
- Результат: `runs/calibration/camera_params.json`, `projections.csv`, `projections.json`.
- 1598 из 5000 проекций попадают в кадр (видимые). Это авторазметка для YOLO.

### Шаг 3 — Подготовка датасета
```bash
python3 train_yolo.py        # Создаёт YOLO-метки из projections.csv, data.yaml
python3 extract_frames.py    # Извлекает нужные кадры из видео в runs/dataset/images/
```
- Метки в формате YOLO: `class x_center y_center width height` (нормализованные).
- Один класс: объект (трак/фура).

### Шаг 4 — Обучение YOLO
```bash
#После установки ultralytics, запустить обучение из train_yolo.py (функция train_yolo)
```
Веса сохраняются в `runs/model/truck_detector/weights/best.pt`.

### Шаг 5 — Детектинг на каждом кадре
```bash
python3 infer_yolo.py
```
- Прогоняет каждое видео через обученную модель.
- Выход: `runs/detections/cam{N}_detections.csv` и `runs/detections/all_detections.csv`.
- Формат: `frame, camera_id, x1, y1, x2, y2, cx, cy, confidence`.
- Можно с отрисовкой боксов на видео (параметр `draw=True`).

### Шаг 6 — Триангуляция 3D-траектории
```bash
python3 triangulate.py
```
- Для каждого кадра собирает детекции ≥2 камер.
- Пересекает лучи обзора (наименьшие квадраты) → 3D-точка (X, Y, Z).
- Выход: `runs/trajectory/trajectory_3d.csv`.
- Если объект виден в 1 камере — 3D не восстанавливается (пропуск).

### Шаг 7 — Валидация
```bash
python3 validate.py
```
- Сравнивает восстановленную траекторию с `SM_AA_track.csv`.
- Выход: `runs/validation/validation_report.csv`, `runs/validation/validation_summary.json`.
- Метрики: средняя ошибка, RMSE, макс. ошибка, ошибки по осям X/Y/Z.

## Формулы

Интринсики:
```
fx = f_mm * W_px / sensor_w_mm
fy = f_mm * H_px / sensor_h_mm
K = [[fx, 0, cx], [0, fy, cy], [0, 0, 1]]
```

Проекция 3D→2D (UE конвенция, обзор вдоль +X):
```
X_cam = R^T @ (X_world - C)
depth = X_cam[0]   # должен быть > 0
u = fx * X_cam[1] / depth + cx
v = fy * X_cam[2] / depth + cy
```

Триангуляция (DLT / наименьшие квадраты):
Для каждой камеры i с лучом (C_i, d_i) минимизируем `сумма || P_i (X - C_i) ||^2`, где `P_i = I - d_i * d_i^T`.
Решение: `X = (сумма P_i)^{-1} @ (сумма P_i @ C_i)`.

## Для нового видео с фурой (продакшн)

После обучения веса `best.pt` можно использовать на любом видео:
```python
from infer_yolo import load_model, infer_video
model = load_model("runs/model/truck_detector/weights/best.pt")
detections = infer_video(cam_id=1, video_path="new_video.mp4", model=model, conf=0.25)
```
Для триангуляции на новом видео нужны параметры камер этого видео (K, R, t).

## Риски

1. **Конвенция координат UE** — левосторонняя система, обзор камеры вдоль +X. Сверять с `SM_AA_track.csv`.
2. **Камера 5 вращается** (yaw меняется покадрово) — экстринсики берутся по каждому кадру отдельно.
3. **Cam2, Cam4 не видят объект** — триангуляция возможна только там, где ≥2 камеры видят объект одновременно.
4. **Закрытия (окклузии)** — объект может быть скрыт; требуется ≥2 одновременных наблюдений для 3D.
5. **Кириллица в CSV** — кодировка cp1251, разделитель `;`.

## Что делает каждый файл

- `camera_calibration.py` — калибровка 5 камер, автогенерация 2D-разметки из 3D-граунд-траута
- `extract_video_meta.py` — извлечение технических параметров видео (разрешение, FPS, кадры)
- `train_yolo.py` — преобразование проекций в YOLO-метки, split train/val, запуск обучения YOLOv8
- `extract_frames.py` — вырезание нужных кадров из видео в папку датасета
- `infer_yolo.py` — инференс обученной модели на видео, запись боксов в CSV
- `triangulate.py` — восстановление 3D-точек из 2D-детекций нескольких камер
- `validate.py` — сравнение восстановленной траектории с граунд-траутом, отчёт с метриками
